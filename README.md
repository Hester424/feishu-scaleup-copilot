## 问题

一位工艺工程师需要调查一次放大异常——某药物从 5L 放大到 500L，关键反应收率下降。

- 文档分散在三个系统中（DMS / LIMS / QMS），需要分别登录、分别搜索
- 找到文档后，哪些案例可比、关键差异在哪，只有资深工程师能判断
- 最终花 2-3 天完成调查报告，大部分时间在找东西和整理信息

**企业不缺文档，缺的是把历史文档快速转化为调查决策的能力。**

## 产品

Evidence-based Process Scale-up Copilot —— 不预测参数、不替代工程师决策，聚焦调查中最耗时的环节：**找案例、做对比、写报告**。

当工程师输入当前放大场景后，系统自动检索历史案例，分析关键差异，判断经验是否可迁移，并生成带证据引用的调查报告草稿。工程师审阅确认后，结论自动沉淀至知识库。

### 差异化价值

| | 传统方式 | Copilot |
|---|---|---|
| **案例检索** | 翻 3 个系统，凭经验判断 | 输入问题，自动检索并解释相关原因 |
| **差异分析** | 手动对比，依赖老工程师 | 自动生成差异对比与经验迁移判断 |
| **调查报告** | 2-3 天手写 | 30 分钟，带证据引用 |
| **知识沉淀** | 经验留在个人脑子里 | 确认后自动回写知识库 |

### 核心创新

1. **把「找文档」升级成「做调查」** — AI 参与调查推理，而不仅仅停留在信息检索
2. **让专家经验沉淀为企业能力** — 每次确认后的结论自动转化为组织知识资产
3. **先创造数据，再创造智能** — 通过真实调查积累结构化知识，逐步演进至参数推荐与风险预警

## 产品流程

```
定义问题 → 证据收集 → 案例比较与分析 → 历史工艺参数 → 调查报告 → 专家确认
```

| 步骤 | 说明 |
|------|------|
| 定义问题 | 结构化录入当前放大场景（产品、规模、关注工艺步骤） |
| 证据收集 | 自动检索相关历史案例，标注相关性理由与评分 |
| 比较分析 | 跨案例关键差异分析，判断经验是否可迁移 |
| 参数推荐 | 展示检索案例中的真实工艺参数记录，可追溯至具体案例 |
| 调查报告 | 自动生成带证据引用、置信度标注的报告草稿，支持导出 |
| 专家确认 | 工程师审阅修正，确认后结论回写知识库 |

## 技术栈

- **前端**：Next.js 16 + React 19 + Tailwind CSS 4
- **AI 推理**：OpenAI GPT-4o-mini（结构化 tool-calling），未配置 API Key 时自动降级为静态分析
- **知识库**：基于标签与关键词的确定性检索（非向量检索），逻辑透明可解释
- **部署**：Vercel
